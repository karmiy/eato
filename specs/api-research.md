# 餐厅数据 API 可行性调研报告

> 调研日期：2026-02-08
> 调研目的：验证"吃哪家"功能所需的餐厅数据 API 可行性

## 一、调研背景

"吃了么"小程序的核心功能"今天吃哪家"需要获取周边餐厅数据，包括：
- 餐厅基本信息（名称、地址、电话）
- 位置信息（经纬度、距离）
- **评分**（用于推荐排序）
- **人均消费**（用于预算筛选）
- **营业时间**（用于过滤未营业餐厅）
- 菜系分类（用于偏好匹配）
- 照片（用于展示）

## 二、调研平台

| 平台 | 调研结果 |
|------|----------|
| 高德地图 | ✅ 可行（推荐） |
| 百度地图 | ✅ 可行（备选） |
| 腾讯地图 | ⚠️ 数据不足 |
| 大众点评 | ❌ 无开放 API |
| 美团 | ❌ 仅限企业合作 |

## 九、混合方案可行性分析

### 9.1 方案概述

同时调用高德和百度 API，将同一家餐厅的数据进行整合，获取最完整的信息。

### 9.2 匹配算法测试

**核心问题**：两个平台使用不同坐标系，如何匹配同一家店？

| 平台 | 坐标系 |
|-----|-------|
| 高德 | GCJ-02（火星坐标） |
| 百度 | BD-09（百度坐标） |

**解决方案**：坐标转换 + 名称匹配

```javascript
// BD09 转 GCJ02 算法
function bd09ToGcj02(bd_lng, bd_lat) {
  const x_pi = Math.PI * 3000.0 / 180.0;
  const x = bd_lng - 0.0065;
  const y = bd_lat - 0.006;
  const z = Math.sqrt(x * x + y * y) - 0.00002 * Math.sin(y * x_pi);
  const theta = Math.atan2(y, x) - 0.000003 * Math.cos(x * x_pi);
  return {
    lng: z * Math.cos(theta),
    lat: z * Math.sin(theta)
  };
}
```

### 9.3 实测匹配结果

| 餐厅名称 | 坐标偏差 | 匹配结果 |
|---------|---------|---------|
| 全聚德(和平门店) | 6.78米 | ✅ 成功 |
| 四季民福烤鸭店(故宫店) | ~0米 | ✅ 成功 |
| 人民大会堂宴会厅 | <10米 | ✅ 成功 |

**结论**：坐标转换后误差 < 10米，配合名称相似度判断，可准确匹配。

### 9.4 数据差异对比

| 餐厅 | 高德评分 | 百度评分 | 高德人均 | 百度人均 | 百度评论数 |

### 9.5 混合数据流程

```
用户请求周边餐厅
        ↓
┌───────────────────┬───────────────────┐
│    高德 API       │     百度 API       │
│   (主数据源)       │    (补充数据)      │
│                   │                   │
│ • 名称、地址       │ • 评论数          │
│ • 评分、人均       │ • 品牌信息        │
│ • 营业时间        │ • 多维度评分       │
│ • 照片 ✅         │                   │
└─────────┬─────────┴─────────┬─────────┘
          ↓                   ↓
      餐厅列表 A          餐厅列表 B
          ↓                   ↓
          └─────────┬─────────┘

                    ↓

```

### 9.6 数据合并策略

| 字段 | 数据来源 | 理由 |

### 9.8 建议

**分阶段实施**：

1. **MVP 阶段**：仅使用高德地图

## 十、最终结论与建议

### 10.1 推荐方案

| 阶段 | 方案 | 理由 |
|-----|------|------|
| **MVP** | 仅高德地图 | 快速上线，照片免费，数据完整度 85% |
| **优化** | 高德 + 百度混合 | 数据完整度 95%，用户体验更好 |

### 10.2 技术要点

**高德地图：**
- `extensions=all` 必须设置
- `types=050000`（餐饮服务）或更细分类型码
- 坐标系：GCJ-02

**百度地图：**
- `scope=2` 必须设置
- 坐标系：BD-09（需转换后匹配）

**混合方案：**
- 坐标转换：BD-09 → GCJ-02
- 匹配条件：距离 < 50米 + 名称相似
- 合并策略：高德为主，百度补充评论数/品牌

### 10.3 注意事项

1. 部分小餐厅可能缺少评分或人均数据，需做好空值处理
2. 注意 API 调用频率和配额限制
3. 混合方案会使 API 调用量翻倍，需评估成本
